# Workshop feedback implementation

- [decision] Work stays on `feat/feedback` for git-bug `43a9999`; no main merge
  or deployment is authorized. Briefing commit `1fb9e04` was restored as
  `51b4fa4`, and unfinished files were copied from the operator-identified Delta
  checkout without changing the originals.
- [decision] The app uses Node's SQLite, Hono, server-rendered HTML, native form
  submission, and package-owned `@giclang/styles` assets. The questionnaire
  wording and item IDs remain frozen; Markdown code markers render as code.
- [lesson] `Referrer-Policy: no-referrer` made native form POSTs send
  `Origin: null` in Chromium and Firefox. `same-origin` retains the Origin
  needed for strict POST validation while withholding cross-origin referrers.
  This was exposed by the first integrated browser run, not synthetic requests.
- [decision] The HTTPS proxy must preserve Host, overwrite X-Forwarded-Proto,
  and be the only public entry point. The server requires an exact Origin match.
  Compose exposes the internal port without publishing it.
- [technique] Real HTTP tests use ephemeral Node listeners and real temporary
  SQLite databases. A SQLite trigger aborting the second wish proves rollback
  of both the response and an already-inserted wish.
- [technique] Sixteen focused Node tests cover access gates, signed-cookie
  expiry, every coded option, duplicate/unknown fields, text/body/wish limits,
  honeypots, closed submissions, one-sided wishes, date-only storage, both CSV
  exports, local asset bytes, startup configuration, and rollback.
- [technique] Twelve browser checks cover Chromium and Firefox desktop/tablet
  workflows, native validation, B1's grid, capped template cloning, submission
  and Back, actual self-hosted font requests, table-only narrow overflow, and
  no-JavaScript submission with all twenty wish pairs. Tablet screenshots were
  inspected. This is not a human pilot or a real-device acceptance claim.
- [technique] Docker build and Compose validation pass. A local bind-mounted
  container smoke check verifies UID 1000, a read-only root, local assets,
  submission, private export, WAL sidecars, empty request logs, and identical
  exported rows after container replacement.
- [technique] Repository verification passes: `pnpm test` (433 tests),
  `pnpm test:compact`, `pnpm typecheck`, `pnpm typecheck:browser`,
  `pnpm build:browser`, `pnpm lint`, and `pnpm test:e2e`
  (114 pass, eight existing desktop-tutor skips). The browser build reports its
  existing large-chunk warning.
- [risk] Root `pnpm fmt:check` fails on the unchanged hex-color-function and
  rotated-rect example descriptions. Separate issue `0bf937a` tracks those
  files; formatting checks on feedback files and changed root manifests pass.
- [risk] Git-bug's mutation helper pushes native refs and exports the formatting

  Do not equate successful export with successful bridge import.
- [decision] The briefing remains active for operator deployment, VPS mount and

## Development defaults and library boundaries

- [decision] Fabian requested root `pnpm dev:feedback` with no setup, then
  required Zod validation and EJS rendering and approved `csv-stringify`.
  Development defaults are committed as `de8695f`.
- [decision] Explicit development mode opens the form on loopback port 3000
  with the public development password and an ignored local database. Admin and
  cookie secrets are generated in memory; environment overrides remain
  available. Production startup still requires separate secrets and a database
  path and stays closed by default.
- [technique] Ran the exact root `pnpm dev:feedback` command with feedback
  environment variables removed. Verified its loopback listener, local database,
  health endpoint, successful login, and authenticated open questionnaire.
- [decision] Zod validates environment configuration, login, coded answers,
  strict field sets, limits, and paired wishes. Form decoding retains duplicate
  scalar fields as arrays for schema rejection. Questionnaire-specific NULL/0
  coding remains explicit after parsing.
- [lesson] `csv-stringify` owns quoting, record delimiters, and formula escaping.
  Its direct-prefix protection does not cover leading spaces; a string cast
  supplies the briefing's whitespace-prefix rule without implementing CSV.
- [technique] Independent review found no blockers in development defaults,
  Zod transport/schema handling, wish pairing, and CSV protection. The 18
  feedback tests and compact repository suite passed before EJS integration.
- [decision] EJS renders fixed, absolute template filenames with escaped
  interpolation for all participant data and raw interpolation only for trusted
  includes. Templates are read per render, so changes appear on refresh without
  another watcher. Docker includes the template directory.
- [technique] Integrated verification passed: 18 feedback tests, 12 browser
  checks, feedback type-check, lint, changed-file Prettier checks, frozen
  dependency install, and Docker build. The exact root development command
  starts without feedback environment settings and renders the authenticated
  EJS questionnaire. A read-only container smoke check exercised login, form,
  escaped validation errors, submission, thanks, and protected CSV export.
- [risk] Root formatting still fails only the two unchanged example descriptions
  tracked by `0bf937a`. Prettier's HTML parser does not support conditional EJS
  attributes; template syntax and output are validated by renderer and browser
  tests, not an HTML-parser formatting check.
