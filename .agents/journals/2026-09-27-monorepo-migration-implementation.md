# Workspace migration

- [decision] The root is a private command orchestrator; core and CLI publishable packages share version `0.1.0`, while content, editor, and desktop packages remain private. No npm publication or origin change was attempted.
- [technique] The installed CLI test packs both packages and installs their tarballs together with npm offline, proving the `workspace:` dependency becomes resolvable package metadata.
- [decision] Editor development compiles core and content before Vite starts and runs both TypeScript projects in watch mode against their package exports. Production and standalone builds use those same exports.
- [lesson] `pnpm add --offline` can fail on missing registry metadata even when package tarballs are cached; normal `pnpm add` reused pinned versions and updated the one workspace lockfile.
- [risk] Docker image acceptance could not run because the Docker daemon was unavailable. The macOS desktop package and development shell built and launched, but packaged Open/Save and preview were not clicked through; do not claim those gates passed.
- [risk] npm authentication returned 401 and registry lookups for `@giclang/core`, `@giclang/cli`, and `gic-lang` returned 404. Confirm scope control and first public version before publishing.
- [lesson] git-bug issue `2612dbd` tracks the Docker and packaged-desktop acceptance gates. The mutation helper's bridge push initially timed out resolving GitHub, but a retry exported the issue; bridge pull still reports its existing import error.
- [lesson] A review flagged the Vite content hook's nonexistent module lookup, but the real Vite module-graph test passed before any fix: glob discovery already updates on create/delete. Removed the ineffective manual invalidation and retained the full reload; focused, compact, Firefox, and PWA tests pass.
- [technique] The Docker image built from the frozen workspace lockfile. In a visible browser, Caddy served bundled Docs and Examples, a sample rendered 1,528 nontransparent Canvas pixels, and the service worker activated at the root scope. After stopping the container, browser navigation to the same origin still loaded Docs and Examples and rendered the sample.
- [risk] The `agent-browser reload` command showed Chrome's network error after the container stopped, although browser navigation worked against the same unavailable origin. The six production PWA lifecycle tests still pass; do not claim this specific reload command proves offline restart until its different behavior is understood.
- [technique] Rebuilt `apps/desktop/src-tauri/target/release/bundle/macos/GiC.app` and `dmg/GiC_0.1.0_aarch64.dmg` from the feature branch; the arm64 executable and disk image exist, and native tests, Rust formatting, and Clippy pass. Did not launch the package against existing user data; the manual Open/Save and preview gate remains in issue `2612dbd`.
- [lesson] The packaged macOS webview lacks a download handler, so its Blob-backed `<a download>` exports are canceled even though PWA/Docker exports pass. Added a format-restricted native Save dialog/write command for desktop PNG and HTML bytes; the PWA keeps its browser downloads.
- [technique] Desktop export tests first failed to compile without the native write boundary, then passed with real temporary files for PNG/HTML bytes, extensions, size bounds, unsupported formats, and write failures. Full core/browser/PWA/native gates and the rebuilt macOS package pass; packaged export clicks still need Fabian's retest.
- [lesson] Reviewing the native export boundary exposed JSON byte-array expansion before the Rust size limit and a blocking dialog inside an async command. Desktop export IPC now sends raw `Uint8Array` bytes through two explicit commands, rejects JSON, uses the dialog callback, and writes on a blocking task. Tests and the rebuilt package pass; the macOS Save dialog still needs manual confirmation.
- [risk] Fabian rebuilt and installed the matching executable, started it after installation, and reported no dialog or alert on export click. Filesystem permissions cannot explain a missing dialog; Preview export buttons were visually identical when disabled. Added shared hover/focus and disabled cues with a red-then-green Firefox test so the next desktop check can distinguish availability from hit-target or command failures. The native export root cause is still unconfirmed.
