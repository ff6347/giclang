# GIC v0.9 Workshop PRD

## Outcome

Published git-bug issue `60b2077`, **PRD: GIC v0.9 workshop environment**, and aligned the vertical roadmap and architecture decisions with the agreed static workshop release.

## Durable observations

- [decision] v0.9 ships static generative graphics as the release gate; animation remains a stretch slice.
- [decision] `gic check` and `gic run` remain required supported interfaces over the shared core. The `run` presentation for recorded drawing commands must be selected before implementation.
- [decision] Monaco replaces the completed textarea prototype and directly consumes browser-neutral diagnostics, formatting, completion, hover, and signature help. LSP and VS Code remain deferred.
- [decision] The primary edition is a dedicated-window Deno-first desktop app; the secondary edition is a tutor-less offline PWA.
- [decision] Desktop fallback order is Pi modules under Deno, narrow Pi boundary ports, Electron, then Tauri with a bundled Node sidecar.
- [decision] One shared UI serves desktop and PWA through narrow platform adapters. One-document workflows, explicit saving, examples, and private recovery stay distinct.
- [decision] PNG requires an exact current successful render. Standalone HTML is one editable offline direct-`file://` artifact with worker cancellation and timeout behavior.
- [decision] The optional tutor is a soft dependency, receives only ephemeral text context after explicit submission, has no editing/shell/web tools, and persists transparent local JSONL sessions.
- [decision] Credentials use protected app-owned plaintext `auth.json` outside the webview rather than an operating-system vault.
- [decision] Managed workspace files update only when unmodified; modified user files are flagged and never overwritten.
- [technique] Production slices terminate at explicit CLI/core, shared-UI, desktop bridge/package, direct-file export, deterministic tutor, real-provider, and PWA lifecycle seams.
- [risk] Deno Desktop viability, Pi streaming/auth compatibility, direct-file Blob workers, and release signing remain mandatory evidence spikes.
- [blocked] Native git-bug refs synchronized, but the configured issue bridge could not access its keyring inside the current nono sandbox.

## Open decisions

- [question] Which OpenCode endpoint and curated provider models are supported?
- [question] Which single-file worker strategy passes Chromium, Firefox, and WebKit when opened directly through `file://`?
- [question] Which package formats, architectures, signing identities, and CI runners form the release matrix?
- [question] How are Windows owner-only credential ACLs implemented and repaired?
- [question] How are managed-file conflicts, session identity, partial JSONL writes, file relationships, and recovery lifecycle presented?
- [question] Which PWA browser matrix and accessibility checks are release gates?

## Issue publication

- [decision] `gic run` executes headlessly in v0.9 and writes ordered GIC `print` output by default. `--show-commands` additionally writes a stable serialization of recorded drawing commands.
- [decision] Image output from the shell is deferred to a separate backend decision; Skia is a future candidate rather than a v0.9 dependency.
- [decision] The approved PRD decomposition was published as 25 open git-bug children of `60b2077`, including four evidence spikes and one non-blocking animation stretch issue.
- [resolved] Git-bug keyring access was granted and every child mutation completed its configured synchronization.
- [technique] Run git-bug reads and mutations sequentially because concurrent commands contend on the repository-wide git-bug lock.
