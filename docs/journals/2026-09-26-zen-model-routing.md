# Zen model routing

- [decision] The integrated tutor keeps its GIC-owned native provider boundary. Rig handles Zen Chat Completions, OpenAI Responses, and Anthropic Messages; no OpenCode CLI or proxy sidecar is required.
- [technique] Zen `/models` provides IDs but no endpoint or pricing metadata. `docs/zen-model-routes.md` records documented families, while the exact native route map admits only documented text-model IDs present in the live catalog.
- [lesson] An HTTP 402 cannot establish protocol incompatibility. With account access, representative GPT, Claude, and Gemini text models returned HTTP 400 through Chat Completions but streamed text through their respective Responses, Messages, and Gemini endpoints.
- [technique] `scripts/zen-smoke.ts` sends bounded text-only requests using an environment-supplied key and reports statuses, text lengths, and terminal markers without logging provider bodies.
- [risk] Rig 0.42's Gemini GenerateContent client puts the key in a query parameter. Gemini has a direct smoke result but no native tutor adapter; its models stay outside the callable picker.
- [decision] Fabian deferred native Gemini integration rather than use the query-key Rig client or introduce a separate HTTP adapter in this branch.
- [risk] Rig maps Responses `max_output_tokens` and Anthropic `max_tokens` to `FinishReason::Length`. Treat that as an incomplete tutor answer rather than recording a successful terminal.
- [question] Fabian has not selected handpicked default OpenRouter model IDs. Keep unknown Zen IDs excluded rather than infer a protocol.
- [verification] Core and compact tests, both typechecks, lint, formatting, native tests, Clippy, 80 Firefox tests, and the packaged macOS build pass. A live packaged GPT/Claude tutor interaction remains to be confirmed; the standalone smoke script and local native HTTP tests cover their protocol paths.
- [decision] Fabian requires models to prove bounded reference-tool support before they become selectable. Direct Zen probes verified search, read, result consumption, and a final text answer for `gpt-6-luna` and `claude-sonnet-5`; Big Pickle's ordinary and tool requests both returned HTTP 403, so its tool capability remains unknown.
- [technique] Rig Core exposes function-tool wire events but not an installed agent executor. The native tutor executes only `search_reference` and `read_reference` against one compile-time bundled file, requires a successful section read, caps the whole request at two tool calls and 90 seconds, and streams only the final answer. The browser removes transient partial text on error.
- [risk] OpenRouter's GPT-6 Sol model is text-capable in the public catalog, but no OpenRouter account-key tool round trip has been verified. The strict capability gate keeps OpenRouter models visible in advanced settings but not callable until tested with that provider.
- [verification] `scripts/zen-reference-smoke.ts` reproduced complete search/read/final turns for the two verified Zen models without logging arguments, reference text, credentials, or response bodies. Local HTTP tests cover all three Zen wire dialects plus OpenRouter; a live packaged Tauri tutor interaction is still unverified.
- [lesson] Two tool-bearing model turns can require a third provider request for the final no-tools answer. The two-call cap is request-wide, but the provider may bill each of the up to three requests; Settings discloses this before key entry.
- [technique] Final answer text is emitted while the stream is open. Cancellation or a failed terminal removes the uncommitted partial message, and an empty or whitespace-only final turn does not complete or persist an answer.
- [lesson] Rig's completion request builder appends its prompt after `.messages(history)` on every call. Reusing the original student question as that prompt during a tool continuation placed the question after the tool results. Preserve prior turns and the current question in one ordered history; pass its last tool-result message as the next builder prompt. Local wire assertions cover Chat Completions, Responses, Messages, and OpenRouter.
- [verification] Bounded direct probes completed search, read, and a final answer for 12 of Fabian's requested Zen IDs and eight exact account-eligible OpenRouter IDs. Other responses included 400, 403, 404, and HTTP 200 without a tool call; those statuses do not establish model tool capability. Zen Space Bunny Free succeeded while Big Pickle returned 403, so free-tier access cannot be generalized across models.
- [decision] Fabian approved the exact 12 Zen and eight OpenRouter IDs for the native tool-proof gate. Earlier Zen probes for `glm-5.3-flash` and `kimi-k3` succeeded but those IDs were not among the 12 approved Zen choices; they remain excluded rather than expanding the requested set silently.
- [technique] Settings' advanced model lists are semantic tables with separate input/output price columns, explicit reference-tool status, Base UI switches, and stable verified-first ordering within each provider. Search still filters before sorting; no model is enabled by default.
- [verification] Core and compact tests, both typechecks, lint, formatting, 93 native tests, Clippy, 81 Firefox tests, and the packaged macOS build pass. The packaged application still needs a live tutor and visual Settings-table check with real provider credentials.
- [lesson] Live native calls showed Zen Space Bunny Free answering after a successful search without a read even when the next request forced `read_reference`; another attempt issued two searches at once. Direct smoke probes had explicitly requested search then read, so their success did not establish that the integrated tutor's strict read gate would work.
- [decision] A completed answer requires one successful bundled-reference lookup; a search excerpt can suffice, while a named section read remains available for details. The two-call and 90-second limits remain, and a no-lookup answer is rejected. The prompt lists section headings derived from the bundled reference instead of sending the full document.
- [technique] Native search checks the full query, then GIC call signatures and descriptive lines matching meaningful query terms by length; it returns nearby lines under their section headings with per-excerpt bounds. The compact heading map and excerpts come from the same bundled reference rather than copying the growing human-facing docs on `main`.
- [verification] An opt-in native Rig smoke against Zen Space Bunny Free, DeepSeek V4.1 Flash, and Claude Sonnet 5 completed with the compact heading map and search-or-read grounding rule. This tests the real provider path without exposing keys or response content, but not the packaged app's credential bridge or visible UI.
- [lesson] Rig 0.42 rejects duplicate provider tool-call IDs while parsing the stream, before the native lookup loop receives calls; a local HTTP fixture confirms the error is redacted and no student-facing text or continuation is emitted.
- [decision] Final-answer text continues to stream before `Stop` for the existing tutor UX. The browser discards partial text after a failed or cancelled run, so documentation must not claim that students never see transient partial output.
- [technique] The Agent transcript uses its scroll container ref on message and status updates to keep streamed responses visible without moving the fixed composer. A long deterministic conversation in Firefox reproduces the prior gap between scroll position and the newest text.
- [lesson] Firefox computed inline and block code at 13 px beside 16 px prose even with `1em` or `inherit` font-size on `code`. Setting the Agent Markdown code and pre elements to `1rem` and inheriting the application font family produces equal rendered size and matching typography.
