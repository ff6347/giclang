Conversation Summary: autoresearch → gic fine-tuning pipeline
Started with an exploration of Karpathy’s autoresearch project — an autonomous ML research loop where an AI agent iteratively modifies a training script, runs 5-minute experiments, and keeps improvements. The key insight is that the human iterates on program.md (the agent’s instructions) rather than the code directly.
Discussed adapting the pattern to consumer hardware: the H100 defaults can be scaled down via smaller models, shorter sequences, lower vocab, and simpler attention patterns. Community forks exist for macOS/MLX, Windows/RTX, and AMD.
Shifted to applying autoresearch not to pretraining but to fine-tuning a small language model — specifically Qwen Coder — where the loop searches over LoRA hyperparameters rather than architecture. Fine-tuning is actually better suited to consumer hardware because meaningful improvements surface faster.
This led to the core project idea: using autoresearch to fine-tune Qwen Coder on gic, Fabian’s minimal visual programming language, and evaluating generated sketches against p5.js/Processing/DBN references. The eval pipeline would use:
∙ Fast metrics (execution success, feature-based Gestalt scores) as a pre-filter
∙ LLM-as-judge (vision model comparing rendered images) for promising candidates — estimated to be affordable, potentially cents per overnight session given gic’s tiny 101×101 canvas
Gestalt principles were identified as a design-aware eval metric and training curriculum — several principles (proximity, similarity, figure/ground, common fate) map directly onto gic primitives and the loop block.
The full gic spec was reviewed. Key observations: OKLCH is underrepresented in Qwen’s training data making fine-tuning high-value, randomSeed enables reproducible benchmarking, the 101×101 canvas keeps judge costs low, and the tools/training-generator/ placeholder in the spec already anticipates the ML pipeline.
Current status: Fabian is working through Crafting Interpreters (jlox stage). The node-canvas render backend is the critical path for the pipeline. Prep work (Gestalt tagging schema, reference sketch collection, benchmark prompt set) can proceed in parallel before the interpreter is complete.​​​​​​​​​​​​​​​​
